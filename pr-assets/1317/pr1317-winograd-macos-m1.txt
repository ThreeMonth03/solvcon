direct BLAS call and one planned Winograd call in the same process. Call order
alternated between rounds. Each round ran in a fresh process so its 3.8 GB
working set was released before the next round. Times are profiler wall times.

The 8 GB system cannot retain this approximately 7.5 GB working set with
enough headroom for an extra warmup. Each route therefore ran as one cold call
in a fresh process. Call order alternated between rounds. SimpleArray inputs
were allocated directly so no duplicate NumPy inputs remained resident. Times
are profiler wall times and include the memory-system behavior during the
call.

This float64 result is a memory-constrained cold-call reproduction, not an
in-cache kernel-throughput measurement. All four pairs favored planned
Winograd, but compression and page reclaim caused more variation than in the
float32 result.

A preliminary float32 run kept all four rounds in one process. Its first two
rounds were near the accepted range, but later calls slowed sharply as the
working set remained resident. It was rejected before the isolated-process
method was adopted:
